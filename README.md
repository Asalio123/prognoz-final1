# Прогнозирование потребления и раннее выявление шоков в муниципалитетах России

**Результат одной строкой: сдвиг в тратах муниципалитета нельзя предсказать заранее — но его можно поймать за месяц. Мы измерили эту границу на 2 016 муниципалитетах и поставили рабочую точку: прогноз с калиброванными интервалами (на «Все категории» чемпионы точнее Prophet-B* на всех горизонтах: 1 322 ₽ против 1 877 ₽ на h=1, −8…−34% RelMAE; в пуле 6 категорий Prophet-B* сильнее: 597 ₽ против 635 ₽ — преимущество подтверждено по §6.2 Положения) + детектор с бюджетом ложных тревог + форвард-2025, сверенный с официальным рядом Лаборатории (+13.3% против факта +14.5%, смещение −1.2 п.п., MAE 1.48 п.п., точнее наивного бенчмарка 2024 года в 2.0×).**

Решение направления «Прогнозирование» онлайн-конкурса СберИндекса 2026.
Презентация для жюри: `reports/presentation.pdf`. Методологический отчёт: `reports/methodology.md`.

## TL;DR для жюри

- **Панель:** 2 016 МО × 24 мес (2023-01–2024-12) × 6 категорий трат, руб/жителя/мес. Валидация — expanding rolling-origin, заморожена до прогонов (`configs/validation.yaml`, коммит e3aa46e от 04.10.2026); все ячейки всех таблиц — строго matched (пересечение ряд × origin × шаг).
- **Прогноз и метрики (К2, К6):** 20 конфигураций в 5 слоях (статистика, Prophet A/B/B*, глобальный LightGBM, zero-shot Chronos-2 и TimesFM 2.5). Контрактная метрика Положения — MAE в рублях/жителя: на главной сводной категории «Все категории» наш чемпион DriftAdjSNaive даёт **1 322 ₽** на h=1 против 1 877 ₽ у Prophet-B* (−555 ₽, −34% RelMAE) и превосходит его на всех горизонтах h=1/3/6/12 (−8…−34%). На полном пуле 6 категорий Prophet-B* лидирует по pooled MAE (597/565/706/897 ₽ против 599/708/778/1248 ₽ у лучшей нашей) — преимущество Prophet на пуле строго подтверждено измерением в соответствии с рамкой §6.2 Положения. На Маркетплейсах h=1 выигрывает LightGBM+news (RelMAE 0.281 / 468 ₽), на Здоровье h=1/6 — TimesFM 2.5 (93 / 123 ₽). Матрица чемпионов ячеек зафиксирована в `outputs/headline/t5_category_champions.csv`.
- **Детекция (К3):** сравнение по фронтиру F1×FAR с бюджетом ложных тревог, disjoint калибровка/измерение. Измеренный итог: при строгом бюджете (FAR ≤ 2/1000 МО-мес) мощность всех методов мала (лучший BOCPD, recall 5.6%) — это цена бюджета, а не слабость метода.
- **Главный отрицательный результат (измерен):** забегающего предупреждения шоков на месячной панели не существует — проверены и отвергнуты пространственное распространение (42 404 соседские пары, лифт ≈1.0, p>0.5), панельный радар (PR-AUC 0.049 против базы 0.048) и refit-от-брейка (ΔMAE +1.1% — хуже). Работает быстрая детекция (0–1 мес) и ранняя интерпретация через новости.
- **Продуктовый артефакт:** форвардный прогноз на 2025-H1 по всем 2 016 МО; проверка на национальном агрегате против официального ряда Лаборатории — средний прогноз +13.3% г/г против факта +14.5% (консервативное смещение −1.2 п.п. — базовый тренд без новых шоков; бенчмарк повторения 2024 года 2.94 п.п. → мы в 2.0× точнее с MAE 1.48 п.п.); полоса 80% PI (±8–10 п.п.) покрывает факт в 6/6 месяцах (`outputs/headline/rc1_o7_forward_by_category.csv`). Полугодие H2 ответственно не публикуется — h=12 backtest-чемпион провалил форвард-контроль (MAE 28.0 п.п. на январе).

## Quickstart

```bash
git clone <url репозитория> && cd repo-forecast
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 1. МГНОВЕННАЯ СВЕРКА ЧИСЕЛ (~0.5 сек, закоммиченные витрины outputs/headline/):
make verify

# 2. Быстрый контур проверки данных и тестов (~10–15 мин):
make smoke

# 3. Полный бэктест-контур (~9–11 ч wall на 8 ядрах):
make data
make reproduce
```

**Мгновенная проверка без многочасовых прогонов:** 14 ключевых витрин результатов закоммичены в репозиторий в каталоге `outputs/headline/` (~260 КБ). Команда `make verify` мгновенно считывает эти витрины и валидирует ключевые числа отчёта за доли секунды.

Платформа: разработано на macOS; на Linux для `make data` нужны `bsdtar` и `curl` (Debian/Ubuntu: `apt install libarchive-tools curl`).

По времени: `make reproduce` — **~9–11 ч wall на 8 ядрах CPU** (доминируют стат-сетка ~2.6 ч и Prophet ~4.5–5 ч; TimesFM ~3 ч CPU можно закомментировать в таргете `reproduce`).

Граница контура честно: `reproduce` покрывает бэктест-ядро и заглавные таблицы отчёта (T1/T2/T3, фронтир и контроли CPD, новости-абляция, радар). Аудит-расширения второго раунда — форвард-2025 (`scripts/28_forecast_2025.py`), Mondrian-интервалы, matched-rate/NAB, энсембли на отложенных origins, пространственная проверка, linlin-цена, внешняя валидация, лестница сложности (`scripts/14, 17_news_kappa, 19–28`, `scripts/rc1_*.py`) — запускаются поверх готового `outputs/` тем же venv, каждый скрипт самодостаточен; в базовый контур не входят из соображений времени и чтобы аудит не был связан с основным прогоном.

Быстрый контур (~10–15 мин, без полного прогона):

```bash
make smoke   # данные → чистая панель → тесты целостности
```

Отдельные числа отчёта воспроизводятся точечно:

| Число в отчёте | Команда |
|---|---|
| Таблица T1 (модель × горизонт, matched cells) | `make tables` → `outputs/T1_model_x_horizon.csv` |
| Значимость (DM/Wilcoxon/Holm, bootstrap) | `make tables` → `outputs/T3_significance.csv` |
| CPD-фронтир | `make cpd` → `outputs/cpd_frontier_v2.csv` |
| Новости-абляция со статистикой | `make news` → `outputs/news_ablation_*.csv` |

## Ограничения (названы первыми)

- 24 месяца = один полный годовой цикл в train максимум; h=12 — ровно один origin: по времени вывод опирается на единственный переход «2023→2024» (мощность на h=12 — только кросс-секция из 2 016 парных ошибок; говорим об этом первыми).
- Данные 2023–2024; прогноз на 2025 — экстраполяция, проверяемая только на национальном агрегате (на уровне МО валидации не существует — данных 2025 нет); категорийный провал форварда на Общепите показан в отчёте явно.
- Забегающего предупреждения шоков на месячной сетке нет (измерено, §4 отчёта): детектор — инструмент мониторинга и интерпретации с задержкой 0–1 мес, не предсказания.
